# Computer setup

The agent runs the bundled shell/PowerShell launcher automatically. `--setup-only` on Unix and `-SetupOnly` on Windows prepare tools without publishing anything. `--check-only` / `-CheckOnly` verify available tools without downloads. Every normal client invocation also checks tools, so using the setup flag first is optional.

Python 3.12+ already installed and usable for HTTPS is reused. Otherwise a private Python 3.13 runtime is installed by [Astral uv](https://docs.astral.sh/uv/guides/install-python/) into `~/.al-style-deploy/python/` (the equivalent user profile directory on Windows). It uses Astral's standalone CPython distribution. Existing system Python, project environments, shell profiles and global PATH remain available as before. `ALSTYLE_CLIENT_STATE` can select another personal state directory.

Native Windows x64/ARM64: missing Git is provided by [MinGit](https://github.com/git-for-windows/git/wiki/MinGit), the upstream Git for Windows package intended for automated use. It is extracted into the employee's state directory. This setup does not require WinGet, Chocolatey, administrator rights, or a GitHub account on the employee computer.

If Windows refuses to start the launcher, inspect `Get-ExecutionPolicy -List` before deciding that IT is required. On a normal fresh Windows client, all scopes can be `Undefined` while the effective default is `Restricted`. For this default case, run the approved company launcher in a new process with `powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File "<skill-directory>/scripts/run.ps1" ...`. This allowance ends with that process and changes no registry/global policy. If the approved company launcher is marked as downloaded, verify it is the file from the company skill archive and use `Unblock-File -LiteralPath "<skill-directory>/scripts/run.ps1"` for that specific file, then retry. Do not unblock project files or arbitrary downloads. Group Policy has precedence over process settings; explicit restrictive corporate policies, AppLocker and installation restrictions require IT authorization. Do not use `Bypass`, change persistent policy, or switch execution methods to defeat those controls. [Microsoft's policy and downloaded-file guidance](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_execution_policies?view=powershell-5.1).

macOS Apple Silicon/Intel: missing Git is installed with existing Homebrew. When Homebrew is unavailable, request [Apple Command Line Tools](https://git-scm.com/install/mac.html) via `xcode-select --install`. The employee confirms the Apple system window. The launcher returns exit 20 / `SETUP_PENDING` and starts no deployment; rerun after the installer completes. Do not poll continuously or repeatedly open installer windows.

Linux/WSL x64/ARM64: missing Git and CA certificates are installed through the available system package manager (apt, dnf, yum, apk, pacman or zypper). The system may request `sudo`; use a user-visible interactive terminal. If admin access is unavailable, ask the company's IT/operator to provide Git and then resume the same launcher. Private Python installation does not require root. Unix setup needs a normal shell, curl or wget, tar, and sha256sum or shasum.

Downloaded uv and Windows Git archives are pinned in `assets/toolchain.conf`, including the publisher's SHA256. A mismatched checksum, failed extraction, failed Python install or failed final tool probe stops the workflow before publication. TLS checks stay enabled. An interrupted download can be retried by running the same launcher; complete installations are reused. Operators update the pins from the official [uv releases](https://github.com/astral-sh/uv/releases) and [Git for Windows releases](https://github.com/git-for-windows/git/releases), then verify packaging and supported systems before distributing a new archive.

After preparation, continue the normal `inspect` → project configuration → `scan` → `publish` → `wait/status` workflow. Setup itself does not log in, create repositories, start deployments or change project files. The employee still needs a personal invitation; app-specific secrets and admin users use the application's actual configuration/authentication flow.
